# Product｜產品定位與功能範圍

## 1. 文件狀態與證據標記

本文件依歷史紀錄與 2026-10-19 現行 Repo 唯讀核對報告整理。

- **使用者明確表達**：歷史對話中由使用者直接提出的產品方向。
- **現行程式碼可見**：唯讀報告指出目前 repo 有相應元件或程式流程。
- **歷史未現況驗證**：過去曾回報完成，但未在本輪重新驗證。
- **待確認／未決策**：缺乏足夠證據，或僅屬討論構想。

## 2. 產品定位

使用者於 2026-10-13 的歷史對話中明確表達的方向：

- 協助想整理、卻不知道從何開始的人，將雜亂轉化為每天做得到、看得見進步的小行動。
- 以整理師角色延伸，把整理收納心法融入功能。
- 重視陪伴感與逐步引導，而非增加使用者的整理負擔。
- 透過斷捨離紀錄，讓使用者有機會與物品道別，並留下過程與成就感。
- 協助使用者逐步養成整理習慣，重新取得空間主導權。

以上是產品方向的歷史依據，不代表所有方向都已透過使用者研究或數據驗證。

## 3. 目前可見的主要功能

依 2026-10-19 現行 Repo 唯讀報告；本次沒有逐項執行 UI 測試。

### 首頁（HomeTab）
- 產品入口與各功能導覽。
- 未登入時提供前往會員頁登入的入口。
- 提供意見回饋表單。
- 本輪只檢查了 GA 事件呼叫，未深入審查其他內容。

### 整理清單（Checklist）
- 整理計時與清單。
- 整理前／後照片。
- 草稿保存與恢復。
- 排程整理相關資料。
- 完成後保存整理紀錄。

### 斷捨離（Declutter）
- 斷捨離流程與紀錄。
- 階段／草稿保存。
- 照片處理。
- 會員頁面可檢視相關紀錄。

### 每日挑戰（Challenge）
- 挑戰進度與每日紀錄。
- 本機 snapshot 與雲端同步。
- Guest 與登入帳號資料銜接。
- 挑戰完成後可開始新一輪。

### 收納推薦（RecommendTab）
- 現行 repo 仍有此分頁，標籤為「收納推薦」。
- 本輪未深入審查其推薦邏輯與商品資料。
- 歷史檢查曾提到：商品資料庫最初可能依 AI 既有知識填入，品名、尺寸與價格的正確性未經驗證（見 `docs/TODO.md`）。

### 會員專區（Member）
- 顯示整理日記、斷捨離紀錄、挑戰進度與統計。
- 提供紀錄刪除操作。
- 提供意見回饋。

## 4. 使用者與身份情境

目前程式至少處理兩種情境：

- Guest：`user === null`，資料主要保存在不帶帳號後綴的 LocalStorage key，照片另有 IndexedDB 快取。
- 登入使用者：LocalStorage key 以 email 後綴區分，部分資料同步到 Supabase。

實際資料隔離仍涉及資料表 RLS 與 Storage 設定；這些後台設定尚未確認。

## 5. UX 原則

- 以小步驟降低整理負擔，避免讓新使用者一開始就面對太多選項。
- **登入前保留功能可見性**：讓使用者能先體驗核心功能，不應不必要地在登入前隱藏功能；登入需求應與資料同步／儲存需求清楚區分。（歷史紀錄：2026-05-12 曾討論未登入狀態的功能可見性與本機資料體驗。）
- UX 修改應先確認使用者需求與既有行為，不要順手移除資料保存或遷移保護。

## 6. 對外宣稱注意事項

歷史文案曾引用「整潔環境降低皮質醇」等健康效果敘述。在查核可信研究之前，不應將這類具體的健康因果敘述直接用於正式產品或行銷文案。

## 7. 早期構想與未決策事項

以下內容曾被討論，但**不是既定需求**，不得寫成已實作功能或已承諾的產品規格：

- 2026-03-26 曾討論照片物品辨識、空間丈量、收納品資料庫、空間與物品分類等構想；現行 Repo 盤點未證實這些已成為目前功能。
- **空間選擇九宮格（未決策）**：歷史 UI 分析指出，3×3 九宮格可能帶來選擇負擔，曾提出凸顯新手推薦或最快完成選項的想法；是否調整由使用者決定。
- 忙碌上班族、家庭整理者、台灣 25–40 歲等 TA 描述，曾在不同討論中被提出；除非使用者另行確認，應視為待驗證的市場假設，不是正式定案。

## 8. 產品決策原則

- 讓整理行動保持低負擔、可開始、可持續。
- 不將早期構想或助手提出的建議自動視為正式產品需求。
- 任何涉及刪除使用者資料、改變登入後資料銜接或本機快取策略的變更，必須先說明影響並取得明確授權。

## 9. 待確認事項

- 目前正式版各功能的實際可用狀態。
- 目前正式名稱、正式網址與品牌定位是否有變動。
- 目標使用者與市場定位是否已經過正式驗證。
- RecommendTab 的商品資料是否已查證。
- Guest 登出後的本機資料與 IndexedDB 快取應保留多久、是否提供清除選項。
- 早期構想是否有任何部分已在其他分支或外部服務實作。
